# Package deploy and install

Two manifests exist in this ecosystem and they are **not interchangeable**:

| File | Tool | Purpose |
| --- | --- | --- |
| `mozhi.toml` | `mozhi` / `mz` (the language) | project manifest for dev, build, test |
| `nx-pkg.json` | `nxc` (the registry) | publishes and installs packages in the nxc library |

All commands below are verified against the latest allowed release
(v3.7.0). Newer builds in the mozhi repository add extra `mz pkg` and
`mz app` commands — they ship with future releases and are documented in
the repository README.

## 1. Scaffold a project

```sh
mozhi new mylib --template minimal   # or --template web
cd mylib
```

The scaffold:

```text
mylib/
├── mozhi.toml
└── main.mz
```

`mozhi.toml` (real format, generated by `mozhi new`):

```toml
[project]
name = "mylib"
version = "0.1.0"
entry = "main.mz"

[server]
host = "127.0.0.1"
port = 8080

[paths]
public = "public"
views = "views"
```

## 2. Everyday project commands

| Command | Purpose |
| --- | --- |
| `mozhi dev` | run the project (`mozhi.toml`) with auto-reload |
| `mozhi serve [--host H] [--port P]` | run without auto-reload |
| `mozhi test [dir]` | run `*.test.mz` files (default `tests/`) |
| `mozhi build [--release]` | verify imports, emit a `dist/` bundle |
| `mozhi lint [path]` | parse checks + basic warnings |
| `mozhi fmt [path]` | re-indent `.mz` files |

Add tests under `tests/`:

```text
mylib/
├── mozhi.toml
├── main.mz
└── tests/
    └── main.test.mz
```

```sh
mozhi test            # runs every tests/*.test.mz
```

With no test files present the command reports
`No *.test.mz files in <dir>` instead of silently passing. Running
`mozhi dev` or `mozhi build` outside a project fails with
`entry 'main.mz' not found (set [project] entry in mozhi.toml)` — that is
the manifest reference the message means.

## 3. Syntax rules that bite beginners

**Function declarations take no colon.** Real terminal output from the
latest release:

```text
error[PARSE001]: unexpected token
  --> bad.mz:3:13
3 | func main():
  |             ^
```

The offending code:

```mozhi
# WRONG — PARSE001 at the colon (3:13)
func main():
    print("hi")

# RIGHT — no colon, brace body
func main() {
    print("hi")
}
```

Mozhi uses braces; a colon after `func main()` is always a parse error
(`PARSE001`, with related `PARSE004` diagnostics). Diagnostics carry a
stable code and a docs URL such as
`https://crossberry-in.github.io/mozhi-doc/errors/PARSE001`.

## 4. Publish to the nxc package registry

Scaffold, fill, publish:

```sh
nxc pkg create mylib          # scaffolds nx-pkg.json + README.md + src/
cd mylib
# copy your .mz sources into src/ and document usage in README.md
nxc login                     # only publishing needs an account
nxc pkg push .                # uploads the package to the public registry
```

`nx-pkg.json` scaffolded by `nxc pkg create`:

```json
{
  "name": "mylib",
  "version": "0.1.0",
  "type": "package",
  "description": "A new NxMirror package",
  "license": "MIT",
  "tags": [],
  "visibility": "public"
}
```

Bump `version` (semantic version) for every push so installers can pin.

## 5. Install from the registry anywhere

```sh
nxc pkg search mylib              # find it in the package library
nxc pkg install you/mylib         # latest
nxc pkg install you/mylib@0.1.0   # pinned
```

Nothing about installing requires an account — search, info and install
are all public operations.

## 6. Mozhi's built-in library registry

Mozhi also has a language-level library registry with automatic download
on first import — verified with the latest release:

```mozhi
import strings from "strings"     # auto-downloads on first run
print(strings.slugify("Hello Mozhi Docs"))   # → hello-mozhi-docs
```

Published libraries include `mozhi-html`, `mozhi-http`, `mozhi-json`,
`mozhi-math-utils`, `mozhi-strings`, `strings`, `datetime` and
`crawler`. The registry index is `mozhi-registry.json` in the
`crossberry-in/mozhi-doc` repository; the next page explains how to add
or update an entry there.
