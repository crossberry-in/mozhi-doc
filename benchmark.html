Analysis

mozhi-mini is a tree-walking interpreter. It walks the AST directly without compiling to bytecode.

mozhi-fast is ~1.25–1.7× faster than mozhi-mini by compiling Mozhi to bytecode and running it on a stack-based VM.

mozhi-fast vs mozhi-mini

Both run the identical Mozhi source.

mozhi-fast has two engines: a bytecode VM (~1.4–1.8× faster than mozhi-mini) and a native codegen (`--native`) that compiles to C with gcc -O2 (~13–26× faster, approaching native speed). Both produce correct 64-bit results where mozhi-mini's 32-bit integers overflow. Full details: docs/mozhi-fast.md.

Benchmark Methodology

  • Platform: x86_64 Linux
  • mozhi-mini: mozhi fib.mz (tree-walking interpreter)
  • mozhi-fast: mozhi-fast fib.mz (bytecode VM)
  • Measurement: median of 3 runs (wall-clock, time.perf_counter)
  • Correctness: Both implementations produce identical results: Fib(28)=317811, Fib(30)=832040, Loop Sum=49999995000000

Benchmark Code

Both implementations run the identical Mozhi source:

fib.mz

fn fibonacci(n) {
    if n <= 1 {
        return n
    }
    return fibonacci(n - 1) + fibonacci(n - 2)
}

echo("Fib(30) = ", fibonacci(30))
